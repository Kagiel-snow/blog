开始学习 C 语言时，Hello World 通常只有几行代码，但从输入文字到看到结果，中间还涉及编辑器、编译器和终端。这篇把这些步骤分开记录，先弄清每一步在做什么，再比较 vi、Vim 和 VS Code 的使用方式。

主要操作以 Windows 的 PowerShell 为例，另列 Linux／macOS 的运行命令。不同终端的命令不要混用。

<!-- more -->

## 先区分编辑器和编译器

| 工具 | 负责什么 | 例子 |
| --- | --- | --- |
| 编辑器 | 编写、修改和保存源代码 | vi、Vim、VS Code |
| 编译工具链 | 把源代码转换并链接成可执行程序 | GCC、Clang、MSVC |
| 终端与命令解释器 | 输入命令、启动工具、查看输出 | 终端窗口中的 PowerShell、Bash 等 |
| 调试器 | 设置断点、逐步执行、检查变量 | GDB、LLDB 等 |

严格说，终端提供输入输出界面，PowerShell、Bash 等命令解释器负责理解命令。初学时容易把两者统称为“终端”，只要注意当前使用的是哪一种命令环境即可。

安装 VS Code 后，还需要准备编译器。Microsoft 的 C/C++ 扩展提供语言支持，但不包含 C/C++ 编译器和调试器。这一点在 [VS Code 的 C/C++ 官方说明](https://code.visualstudio.com/docs/languages/cpp)中有明确区分。

## 写出第一个完整程序

新建一个名为 `hello.c` 的文件，保存以下内容：

```c
#include <stdio.h>

int main(void)
{
    printf("Hello, World!\n");
    return 0;
}
```

文件后缀是 `.c`。保存时检查实际名称，避免变成 `hello.c.txt`。代码中的括号、引号和分号使用英文半角符号；中文输入法下的 `“ ”`、`；` 不能直接替代它们。

### 头文件提供函数声明

```c
#include <stdio.h>
```

这是一条预处理指令，用来包含标准输入输出头文件。`stdio` 来自 standard input/output。使用 `printf` 之前，需要让编译器看到它的声明。

这行末尾不写分号。头文件也不是简单地“把 printf 的全部实现复制进来”；函数实现通常由标准库提供，之后通过工具链完成链接。

### main 是程序入口

```c
int main(void)
```

对于这里讨论的普通宿主环境程序，`main` 是程序入口函数。`int` 表示它返回整数，括号里的 `void` 表示不接收参数。后面的 `{` 和 `}` 包围函数体。

先使用这个明确的写法，不把 `void main()` 当作通用标准写法。关于入口与返回值，可以对照 [C11 委员会草案 N1570 的 5.1.2.2 节](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)。本文编译时选择 C17，示例使用的是这些版本共同支持的基础写法。

### printf 输出字符串

```c
printf("Hello, World!\n");
```

`printf` 是标准库函数，这里向标准输出写入文字；从终端运行且没有重定向时，通常就显示在终端中。

- 双引号括住字符串，双引号本身不输出。
- `\n` 是换行转义序列，会产生换行，而不是显示反斜杠和字母 n。
- 圆括号内是传给函数的参数。
- 末尾的分号结束这条语句。

单引号与双引号的用途不同，不要把整段文字改成 `'Hello, World!'`。反斜杠也不是普通斜杠：`\n` 换行，`/n` 则只是两个普通字符。

### return 0 表示成功结束

```c
return 0;
```

这一句从 `main` 返回，向运行环境报告成功结束。它不会在屏幕上打印数字 0。C99 及以后，执行到 `main` 的末尾相当于返回 0；入门笔记中保留这一句，便于看清函数的返回过程。

## 在 Windows 上准备 GCC

这里选择 MSYS2 提供的 UCRT64 工具链，适用于通常的 x64 Windows 环境。安装步骤以 [MSYS2 官网](https://www.msys2.org/)和 [VS Code 的 MinGW 教程](https://code.visualstudio.com/docs/cpp/config-mingw)为依据。若是其他系统架构，应先选对应的工具链。

1. 从 MSYS2 官网下载安装程序，记录安装目录。以下假设使用默认的 `C:\msys64`。
2. 打开 **MSYS2 UCRT64** 终端，先按官网说明完成系统更新；如果更新要求关闭终端，重新打开后继续完成更新。
3. 在 MSYS2 终端中安装工具链：

```bash
pacman -S --needed base-devel mingw-w64-ucrt-x86_64-toolchain
```

出现软件包组选择时，直接回车选择默认项目，再按提示确认。`pacman` 是 MSYS2 中的包管理命令，这条命令不要直接粘到普通 PowerShell 中运行。

4. 在 Windows 的“编辑账户的环境变量”中，编辑用户 `Path`，**新增** `C:\msys64\ucrt64\bin`。安装位置不同就使用实际路径，不要覆盖原有条目。
5. 重新打开 PowerShell；如果 VS Code 已经运行，也重新打开它。在新终端检查：

```powershell
gcc --version
gdb --version
```

能显示版本，说明命令可以找到对应工具。若出现“无法将 gcc 识别为命令”，先检查安装目录、Path 和终端是否重新打开，还没有到修改 C 代码的阶段。

## 编译与运行是两个步骤

先建立并进入一个练习目录，把 `hello.c` 保存在其中。例如在 PowerShell 中执行：

```powershell
mkdir c-notes
cd c-notes
```

保存源文件后，在同一个目录编译：

```powershell
gcc -std=c17 -Wall -Wextra -pedantic hello.c -o hello.exe
```

| 部分 | 作用 |
| --- | --- |
| `gcc` | 调用 GCC 驱动程序 |
| `-std=c17` | 选择 C17 标准 |
| `-Wall -Wextra` | 启用常用和额外的警告；不代表所有警告 |
| `-pedantic` | 对所选标准要求诊断的部分非标准写法给出诊断 |
| `hello.c` | 输入源文件 |
| `-o hello.exe` | 指定输出文件名 |

编译成功时，终端可能没有任何文字输出。确认没有错误后，再执行：

```powershell
.\hello.exe
```

预期输出为：

```text
Hello, World!
```

PowerShell 中的 `.\` 表示当前目录。编译命令生成程序，运行命令才启动程序；修改 `hello.c` 后，要保存并重新编译，旧的 `hello.exe` 不会自动变化。

Linux／macOS 在已经安装 GCC 或 Clang 的前提下，可采用下面的命令：

```bash
cc -std=c17 -Wall -Wextra -pedantic hello.c -o hello
./hello
```

`cc` 通常指向系统的 C 编译器，具体可能是 GCC 或 Clang。Linux 上按所用发行版安装开发工具；macOS 通常通过 `xcode-select --install` 安装命令行开发工具。这里的 `./hello` 与 Windows 的 `.\hello.exe` 属于不同环境下的写法。

## 源文件怎样变成可执行文件

入门时可以按下面四个阶段理解工具链的工作：

```text
源代码 → 预处理 → 编译 → 汇编 → 链接 → 可执行文件
```

预处理负责处理 `#include` 等指令；狭义的编译把处理后的 C 代码转换为汇编代码；汇编得到目标文件；链接把目标文件与需要的库等组合起来，生成可执行文件。

日常说的“编译程序”往往把这些阶段合在一起说。前面的 `gcc ... -o hello.exe` 默认会完成所需的编译和链接步骤。

如果想观察中间结果，可以在同一目录依次执行：

```bash
gcc -std=c17 -E hello.c -o hello.i
gcc -std=c17 -S hello.i -o hello.s
gcc -c hello.s -o hello.o
gcc hello.o -o hello.exe
```

这组命令按 Windows 的最终文件名举例。Linux／macOS 最后一步可用 `-o hello`。`-E`、`-S`、`-c` 分别控制停在预处理、生成汇编和生成目标文件的阶段，定义见 [GCC 的编译选项文档](https://gcc.gnu.org/onlinedocs/gcc/Overall-Options.html)。第一次练习不要求逐个分析中间文件，只需知道 `.c` 是源文件，`.o` 通常还不能直接运行。

## 使用 vi 和 Vim 编辑代码

vi 是传统的终端文本编辑器，Vim 在 vi 的基础上扩展了许多功能。有的系统中 `vi` 实际启动的是 Vim 或兼容实现，但不能默认所有环境都相同。下面以 Vim 为主，基础输入和保存操作也适用于常见 vi。

Windows 并不默认提供 Vim。可从 [Vim 官网](https://www.vim.org/download.php)安装；若已在使用 MSYS2，也可以在 MSYS2 终端执行 `pacman -S vim`，然后继续在该终端中使用 Vim。不要因为 MSYS2 中能启动 Vim，就假设 PowerShell 中也配置好了同名命令。

在能找到 Vim 的终端中，进入保存代码的目录：

```bash
vim hello.c
```

如果环境只有 vi，则使用 `vi hello.c`。文件存在时打开现有内容，不存在时开始编辑新文件；保存后才会写入磁盘。

### 先掌握模式切换

| 状态 | 主要用途 | 常见进入方法 |
| --- | --- | --- |
| 普通模式 | 移动、删除、复制等操作 | 通常打开文件时进入；按 `Esc` 返回 |
| 插入模式 | 输入代码文字 | 普通模式下按 `i` |
| 命令行模式 | 保存、退出、设置选项 | 普通模式下按 `:` |

第一次可以只走一遍最短流程：

1. 输入 `vim hello.c` 打开文件。
2. 按 `i`，进入插入模式，输入前面的 C 程序；文件已有内容时，不必重复输入。
3. 按 `Esc` 回到普通模式。
4. 输入 `:wq`，再按回车，保存并退出。
5. 回到终端，使用前面对应系统的命令编译和运行。

`:wq` 是在 Vim 内输入的命令，`gcc ...` 是回到终端后输入的命令。最开始把这两个位置分清，就能少一些操作上的混乱。

### 再补充几个常用操作

下表中的按键从普通模式开始；冒号命令和搜索内容输入完后按回车。

| 操作 | 作用 |
| --- | --- |
| `h`、`j`、`k`、`l` | 分别向左、下、上、右移动 |
| `x` | 删除光标处的字符 |
| `dd` | 删除当前行 |
| `yy`，随后 `p` | 复制当前行，再粘贴到当前行下方 |
| `u` | 撤销上一步修改 |
| `/printf` | 向后搜索 printf |
| `:w` | 保存，继续编辑 |
| `:q` | 退出；有未保存修改时通常会阻止退出 |
| `:wq` | 保存并退出 |
| `:q!` | 放弃未保存的修改并退出 |
| `:set number` | 显示行号 |

在 Vim 中还可以用 `Ctrl+r` 重做，或在终端运行 `vimtutor` 进行交互练习。它们属于 Vim 的常用功能，不应直接当作所有原始 vi 实现都具有的功能。基础模式与退出方法可以查阅 [Vim 用户手册](https://vimhelp.org/usr_02.txt.html)。

## 使用 VS Code 编辑同一个程序

VS Code 更接近通常的图形化编辑习惯。以 Windows 为例，可以按下面的顺序操作：

1. 安装 VS Code，在扩展栏搜索 **C/C++**，确认发布者是 Microsoft 后安装。
2. 通过“文件 → 打开文件夹”打开前面的 `c-notes` 目录。
3. 在左侧文件列表打开或新建 `hello.c`，输入代码并按 `Ctrl+S` 保存。
4. 通过“终端 → 新建终端”打开集成终端，确认当前目录就是保存文件的目录。
5. 在 PowerShell 终端执行前面的 `gcc ... -o hello.exe`，成功后执行 `.\hello.exe`。

如果 `code` 命令已加入 Path，也可以在练习目录执行 `code .` 打开当前文件夹。找不到这个命令时，直接使用菜单打开文件夹即可，不影响写程序。

先用终端完成一次编译，能够确认编译器和文件位置都正确。之后再配置运行按钮和调试器，会更容易判断问题出在哪里。

### 补全、编译和调试分别配置

Microsoft C/C++ 扩展可以提供补全、函数提示和诊断。如果编译成功，但 `stdio.h` 仍有红色波浪线，可打开命令面板 `Ctrl+Shift+P`，查找 **C/C++: Edit Configurations (UI)**，将编译器路径设为实际的 GCC，例如 `C:\msys64\ucrt64\bin\gcc.exe`，C 标准选择 C17。

编辑器的红色提示来自语言分析，终端中的编译结果来自编译器，两者不是同一个过程。补全配置不正确，不一定表示代码无法编译；编辑器没有提示，也不等于代码没有问题。

需要调试时，编译命令加入 `-g`：

```powershell
gcc -std=c17 -Wall -Wextra -pedantic -g hello.c -o hello.exe
```

然后在代码行号旁点击设置断点，打开“运行和调试”，按 C/C++ 扩展的提示选择 GCC／GDB 配置。若需要手动核对，`program` 应指向生成的 `hello.exe`，调试器应指向同一工具链的 `gdb.exe`。VS Code 的[调试教程](https://code.visualstudio.com/docs/cpp/config-mingw#_debug-helloworldcpp)提供了具体操作；其示例是 C++，应用到本文时应使用 `hello.c` 和 `gcc`，不直接照搬 `.cpp` 与 `g++`。

初次运行 Hello World，不需要先手写一整套 `.vscode` 配置。等到需要反复编译或调试时，再理解 `tasks.json` 管编译任务、`launch.json` 管调试启动、`c_cpp_properties.json` 管语言分析设置，会更容易记住它们的作用。

## 哪个更适合初学者

| 比较项 | vi／Vim | VS Code |
| --- | --- | --- |
| 初次编辑 | 需要先记住模式和保存退出方式 | 图形界面直观，编辑习惯接近普通文本工具 |
| 终端环境 | 适合通过终端编辑，远程服务器上也常用 | 桌面使用方便；远程开发需要相应支持和配置 |
| 补全与导航 | Vim 可扩展，但完善配置需要额外学习 | 安装并配置 C/C++ 扩展后较容易使用 |
| 调试体验 | 可以与调试工具配合，使用方式依赖配置 | 断点、变量和调用栈的图形界面较直观 |
| 需要投入的学习 | 先学习模式操作，再逐步扩展 | 先了解工作区、扩展、终端与编译器的关系 |

**如果当前目标是学会 C 语言，我更建议先用 VS Code 作为主要编辑器，同时掌握 vi／Vim 的基础操作。** 这个建议主要考虑入门成本：在语法、编译和编辑器都还不熟悉时，图形界面更方便定位文件和查看错误。

如果课程明确要求终端操作，或者经常登录 Linux 服务器，Vim 就更值得优先练习。熟悉以后，两种编辑器都可以完成实际开发，不能仅凭“是否全键盘操作”判断哪一种更专业。编辑器也不会改变 C 语言本身的规则。

## 出错时按步骤排查

| 现象 | 优先检查 |
| --- | --- |
| 找不到 `gcc` | 编译器是否安装、Path 是否正确、新终端是否读取了配置 |
| 提示找不到 `hello.c` | 当前目录、文件是否保存、真实后缀是否为 `.c` |
| 编译提示缺少分号或括号 | 报错行及其上一行，检查半角标点和括号配对 |
| 修改后输出没有变化 | 是否保存、是否重新编译成功、是否运行了正确目录中的程序 |
| 编译失败后还能运行 | 目录里可能仍有旧程序；旧程序能运行不表示本次编译成功 |
| 双击程序窗口一闪而过 | 程序可能已经正常结束；从终端运行以保留输出 |

不需要为了让窗口停住就在第一个程序里加入 `system("pause")`。从已打开的终端运行，可以直接看到输出，也避免依赖 Windows 特有命令。

## 留下三个小练习

1. 把输出改为 `Hello, C!`，保存、重新编译并运行。
2. 在字符串中加入第二个 `\n`，观察换行位置。
3. 暂时删除 `printf` 语句后的分号，编译并阅读第一条错误，再补回分号重新编译。

这几步分别检查修改是否进入新程序、转义序列怎样影响输出，以及编译错误如何定位。先能独立完成“编辑—保存—编译—运行”，再继续学习变量和输入输出。
