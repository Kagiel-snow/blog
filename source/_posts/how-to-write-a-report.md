大学里的报告（<span lang="ja" translate="no">レポート</span>）和高中的作文、读后感不是一回事。作文可以写感受，报告要回答一个问题，并用证据说服读者。很多报告分数不高，问题不在知识不够，而在于没有写清楚“这篇报告要回答什么、结论是什么、凭什么这样说”。

这篇按写作的顺序整理：先弄清报告的类型，再定问题、搭结构、写段落，最后处理引用和检查。在日本的课堂上，报告大多要用日语写，所以后半部分专门整理日语报告的文体和常用表达。

<!-- more -->

## 报告和作文的区别

| | 作文、感想文 | 报告 |
| --- | --- | --- |
| 目的 | 表达自己的感受和想法 | 回答问题，提出有根据的主张 |
| 依据 | 个人经验 | 文献、数据、实验、调查 |
| 主观表达 | 可以 | 尽量避免，“我觉得”要有依据支撑 |
| 结构 | 比较自由 | 序论、本论、结论 |
| 引用 | 一般不要求 | 必须标明出处 |

报告的核心可以浓缩为一句话：**问题 + 主张 + 依据**。读者读完后，应该能说出“这篇报告问了什么，回答是什么，理由是什么”。

## 先弄清是哪一种报告

| 类型 | 日语 | 要求 | 例题 |
| --- | --- | --- | --- |
| 说明型 | <span lang="ja" translate="no">説明型</span> | 整理、解释某个知识 | 说明 TCP 与 UDP 的区别 |
| 论证型 | <span lang="ja" translate="no">論証型</span> | 对一个问题提出主张并论证 | 大学是否应该全面采用线上授课 |
| 实验/调查报告 | <span lang="ja" translate="no">実験レポート・調査報告</span> | 报告方法、结果和考察 | 测定单摆的周期 |
| 文献综述 | <span lang="ja" translate="no">文献レビュー</span> | 整理已有研究，找出问题 | 关于日语学习者的敬语习得的研究 |

题目里的动词就是线索：“说明”“整理”“比较”偏向说明型；“论述”“考察”“你怎么看”偏向论证型。动笔前先确认老师要的是哪一种，答非所问是报告最常见的失分原因。

## 从题目到问题

老师给的题目往往很大，例如“论述 AI 对社会的影响”。直接写会变成什么都谈一点、什么都没谈透。需要把题目缩小成一个可以回答的问题。

```text
题目：AI 对社会的影响
↓ 限定领域
AI 对教育的影响
↓ 限定对象和方面
生成式 AI 对大学生写报告的影响
↓ 变成一个问题
大学是否应该允许学生在写报告时使用生成式 AI？如果允许，需要什么条件？
```

好问题的标准：

- **可以回答**：能在规定的字数内，用能找到的资料回答。
- **有讨论价值**：答案不是显而易见的，存在不同看法。
- **范围明确**：对象、时期、地区清楚。

## 结构：序论、本论、结论

| 部分 | 日语 | 篇幅 | 内容 |
| --- | --- | --- | --- |
| 序论 | <span lang="ja" translate="no">序論</span> | 约 10～15% | 背景、问题、本报告的主张（或目的）、结构预告 |
| 本论 | <span lang="ja" translate="no">本論</span> | 约 70～80% | 论据、分析、反论及其回应 |
| 结论 | <span lang="ja" translate="no">結論</span> | 约 10～15% | 总结回答、意义、局限和今后的课题 |

### 序论写什么

一个好的序论包括四个要素：

1. **背景**：为什么这个问题重要。
2. **问题**：这篇报告要回答的具体问题。
3. **主张**：回答是什么（说明型则写目的）。
4. **结构预告**：接下来各节会讲什么。

报告不是推理小说，结论应该在序论就亮出来。读者知道了终点，才能判断每一段论证是否在朝那里走。

### 本论怎样展开

本论的每一节都应该支撑主张。论证型报告的常见结构：

```text
第 1 节：论据 1（及其证据）
第 2 节：论据 2（及其证据）
第 3 节：预想的反论，以及对它的回应
```

处理反论非常重要。只写对自己有利的材料，读者会怀疑你是否考虑过其他可能。主动提出最有力的反对意见，再说明为什么它不能推翻自己的主张（或者在什么条件下它是对的），论证才显得可靠。

### 结论写什么

- 用一两句话再次回答序论中的问题。
- 总结本论中的主要依据。
- 说明本报告的局限（资料的范围、没有讨论的方面）和今后的课题。

结论里**不要**加入本论中没有出现过的新论据，也不要突然换成另一个结论。

### 实验报告的结构

实验报告有自己的固定格式：

| 部分 | 日语 | 内容 |
| --- | --- | --- |
| 目的 | <span lang="ja" translate="no">目的</span> | 这个实验要确认什么 |
| 原理 | <span lang="ja" translate="no">原理・理論</span> | 相关理论和公式 |
| 方法 | <span lang="ja" translate="no">方法</span> | 器材、步骤，详细到别人可以重复 |
| 结果 | <span lang="ja" translate="no">結果</span> | 测量数据、表、图，只写事实 |
| 考察 | <span lang="ja" translate="no">考察</span> | 解释结果、与理论比较、分析误差原因 |
| 结论 | <span lang="ja" translate="no">結論</span> | 是否达到目的 |

最常见的错误是把“考察”写成“感想”。“实验很有趣”“下次要更认真”不是考察。考察要回答：结果和理论值相差多少？原因可能是什么？怎样验证这个原因？

## 写好段落

### 一个段落，一个论点

每个段落的第一句是**中心句**（<span lang="ja" translate="no">トピック・センテンス</span>），直接说出这一段的论点；后面的句子是支撑句，提供理由、例子、数据；需要时最后一句做小结或承接下一段。

```text
中心句：生成式 AI 可以降低写作的入门门槛。
支撑句：对于不擅长组织结构的学生，AI 生成的大纲可以提供一个起点。
支撑句：例如，某大学的调查显示……（出处）
小结：因此，在构思阶段使用 AI，对初学者有一定帮助。
```

只读每段的第一句，就应该能看懂整篇报告的论证脉络。写完后可以用这个方法检查。

### 区分事实与意见

| 种类 | 例 | 需要什么 |
| --- | --- | --- |
| 事实 | 2024 年该校报告提交数为 1200 份 | 出处 |
| 意见 | 这个政策是有效的 | 理由和证据 |
| 推测 | 今后这个比例可能还会上升 | 推测的依据 |

报告中的意见必须由事实支撑，推测要用推测的表达方式（「<span lang="ja" translate="no">〜と考えられる</span>」「<span lang="ja" translate="no">〜可能性がある</span>」），不要把推测写成断定。

### 论证的常见缺陷

| 缺陷 | 例子 | 问题 |
| --- | --- | --- |
| 以偏概全 | 我身边的三个朋友都……，所以大学生都…… | 样本太少、有偏 |
| 因果倒置 | 成绩好的学生都用 AI，所以 AI 提高成绩 | 可能是成绩好的学生更愿意尝试新工具 |
| 诉诸权威 | 某名人说……，所以是对的 | 需要看论证本身 |
| 稻草人 | 把对方的观点歪曲成极端版本再反驳 | 没有回应真正的反论 |
| 循环论证 | 这很重要，因为它很有意义 | 理由只是换了个说法 |

## 引用与参考文献

### 为什么必须引用

- 区分哪些是别人的观点、哪些是自己的观点。
- 让读者可以核实依据。
- 避免剽窃（<span lang="ja" translate="no">剽窃・盗用</span>）。不标出处使用别人的文字或观点，即使是无意的，也是严重的学术不端。

### 两种引用方式

**直接引用**：原文照搬，用引号括起来，并标出处和页码。

<div lang="ja" translate="no">

田中（2020）は「言語の習得には、意味のあるインプットが不可欠である」（p.45）と述べている。

</div>

**间接引用（概括）**：用自己的话概括，仍然要标出处。

<div lang="ja" translate="no">

田中（2020）によれば、言語習得においては意味のあるインプットが重要である。

</div>

直接引用要少用，篇幅占比过大的报告会被认为没有自己的分析。引用之后一定要接上自己的解释：这段引文说明了什么，和自己的论证有什么关系。

### 参考文献列表

文末列出所有引用过的文献。格式因学科而异（APA、SIST 02、各学会的格式），以老师的要求为准。常见要素：

```text
书：  著者（出版年）『书名』出版社.
论文：著者（出版年）「论文题目」『期刊名』卷（号），起止页.
网页：作者或机构（发布年）「页面标题」URL（访问日期）.
```

网页资料要写访问日期，因为内容可能更改或消失。优先使用学术论文、官方统计、政府文件等可靠来源；个人博客、匿名网站、维基百科一般不作为主要依据，可以作为找到原始资料的线索。

### 使用生成式 AI 时

如果课程允许使用 AI，要遵守课程的规定，并注意：

- AI 生成的内容可能有事实错误，生成的“参考文献”可能根本不存在，所有信息都要回到原始资料核实。
- 按要求说明使用了什么工具、用在哪个环节。
- 报告的论证和判断应该是自己的。

## 日语报告的文体

### 使用「だ・である」体

日语报告统一使用普通体（<span lang="ja" translate="no">だ・である体</span>），不用「<span lang="ja" translate="no">です・ます</span>」体，两者也不能混用。名词和形容动词句尾用「<span lang="ja" translate="no">である</span>」比「<span lang="ja" translate="no">だ</span>」更正式。

| 口语、です・ます | 报告体 |
| --- | --- |
| 〜です | 〜である |
| 〜と思います | 〜と考えられる／〜と考える |
| 〜でしょう | 〜であろう／〜と推測される |
| 〜じゃない | 〜ではない |
| 〜けど | 〜が／〜けれども |
| 〜なので | 〜であるため／〜ので |
| 〜って | 〜という |
| すごく、とても | 非常に、きわめて |
| いろいろな | さまざまな |
| だんだん | 次第に |
| ちょっと | 少し、やや |
| やっぱり | やはり |
| 〜とか | 〜や〜など |
| でも、だけど（句首） | しかし、だが |
| なんで | なぜ |

### 避免主观和口语化的表达

| 避免 | 原因 | 改为 |
| --- | --- | --- |
| 私は〜と思う | 显得只是个人感想 | 〜と考えられる／以上のことから〜といえる |
| 〜ですよね、〜じゃないですか | 口语、向读者寻求同意 | 删除，直接陈述 |
| ！、？の多用 | 情绪化 | 用句号 |
| 絶対に、必ず | 过度断言 | 〜といえる／〜可能性が高い |

「<span lang="ja" translate="no">思う</span>」不是完全禁止，在结论中表明自己的立场时可以用「<span lang="ja" translate="no">〜と考える</span>」。关键是意见要有依据。

### 常用表达

**序论**

<div lang="ja" translate="no">

- 近年、〜が注目されている。
- 本レポートでは、〜について考察する。
- 本稿の目的は、〜を明らかにすることである。
- 以下、第 2 節では〜、第 3 節では〜を論じる。

</div>

**本论**

<div lang="ja" translate="no">

- 〜によると、〜という。（引用）
- 〜の例として、〜が挙げられる。
- 〜と〜を比較すると、〜ことがわかる。
- 表 1 に示すように、〜。
- 確かに〜という見方もある。しかし、〜。（处理反论）
- その理由は、〜からである。

</div>

**结论**

<div lang="ja" translate="no">

- 以上のことから、〜といえる。
- 本レポートでは、〜について論じてきた。
- 今後の課題として、〜が残されている。

</div>

「<span lang="ja" translate="no">確かに〜。しかし〜</span>」是处理反论的固定句式：先承认对方观点的合理部分，再说明自己为什么仍然坚持主张。

## 写作的流程

1. **确认要求**：题目、字数、格式、截止日期、是否允许使用 AI。
2. **调查**：查文献和资料，边读边记下出处。
3. **定问题和主张**：用一句话写出“问题是……，我的回答是……”。
4. **写大纲**：列出各节标题和每段的中心句。
5. **写初稿**：先写完，不要边写边改。本论可以先写，序论和结论最后写。
6. **修改**：检查论证是否连贯，删除与主张无关的内容。
7. **检查格式**：引用、参考文献、图表编号、页码。

## 提交前的检查清单

- [ ] 回答了题目要求的问题吗？
- [ ] 序论中写明了问题和主张吗？
- [ ] 每个段落只有一个论点，第一句是中心句吗？
- [ ] 事实都有出处吗？意见都有依据吗？
- [ ] 考虑并回应了反论吗？
- [ ] 结论与序论的主张一致吗？没有加入新论据吗？
- [ ] 文体统一为「だ・である」吗？没有口语表达吗？
- [ ] 引用格式正确、参考文献完整吗？
- [ ] 图表有编号和标题，并在正文中提到了吗？
- [ ] 字数符合要求吗？错别字检查过了吗？

最后一个建议：写完后隔一段时间再读一遍，或者出声读。很多读不通的句子，默读时会被跳过，读出声就能发现。
