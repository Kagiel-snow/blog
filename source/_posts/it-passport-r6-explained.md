IT 护照考试（<span lang="ja" translate="no">IT パスポート試験</span>，常简称 i パス）是日本 IPA（情報処理推進機構）主办的国家考试，面向所有使用 IT 的社会人和学生，考查 IT 基础知识以及经营、管理方面的常识。它采用 CBT 方式，全年都可以在考场电脑上应试。

IPA 每年从 CBT 实际出题中抽出 100 题作为“公开问题”发布。令和 6 年度分于 2024 年 4 月 21 日公开。这篇根据公开问题的分布和出题倾向，按领域整理考点并逐个讲解。

说明：为了避免照搬原题，文中的例题都是按同一考点**自编的类题**，不是公开问题的原文。原题、答案可以在 IPA 官网的「<span lang="ja" translate="no">過去問題</span>」页面免费下载，建议对照练习。

## 考试基本信息

| 项目 | 内容 |
| --- | --- |
| 题数 | 100 题，四选一 |
| 时间 | 120 分钟 |
| 评分 | IRT（项目反应理论）计分，满分 1000 分 |
| 合格标准 | 总分 600 分以上，且战略、管理、技术三个领域各 300 分以上 |
| 备注 | 100 题中有 8 题是用于评估今后题目的试测题，不计入得分 |

三个领域都有最低分要求，偏科不能合格。即使技术领域很强，管理领域低于 300 分也会不合格。

## 一、战略系

### 投资回收期（计算）

**类题**：<span lang="ja" translate="no">新システムの導入に 1,200 万円を投資した。導入後、毎年 300 万円の費用削減効果があり、システムの運用費が毎年 60 万円かかる。投資額を回収するのに何年かかるか。</span>

```text
每年的净效果 = 300 − 60 = 240 万日元
回收期 = 1200 / 240 = 5 年
```

关键是先算出每年的**净**现金流入，把运营费用扣掉。如果每年的效果不同，就逐年累加，看哪一年累计超过投资额。

### 损益计算书（计算）

损益计算书（<span lang="ja" translate="no">損益計算書</span>，P/L）的利润分为几个层级：

```text
销售额（売上高）
− 销售成本（売上原価）
= 销售毛利（売上総利益）
− 销售费用及一般管理费（販売費及び一般管理費）
= 营业利润（営業利益）            ← 本业的盈利能力
+ 营业外收入 − 营业外费用          （利息、汇兑损益等）
= 经常利润（経常利益）            ← 日常经营活动的总体盈利
+ 特别利润 − 特别损失              （出售固定资产、灾害损失等）
= 税前利润（税引前当期純利益）
− 法人税等
= 当期净利润（当期純利益）
```

**类题**：<span lang="ja" translate="no">売上高 1,000、売上原価 600、販売費及び一般管理費 250、営業外収益 20、営業外費用 30 のとき、経常利益はいくらか。</span>

```text
売上総利益 = 1000 − 600 = 400
営業利益   = 400 − 250 = 150
経常利益   = 150 + 20 − 30 = 140
```

常见陷阱是把营业外项目算进营业利润。记住：**营业**利润只看本业。

### 损益平衡点

```text
损益平衡点销售额 = 固定费 / (1 − 变动费率)
变动费率 = 变动费 / 销售额
```

例：固定费 400 万，变动费率 60%，损益平衡点 = `400 / 0.4 = 1000 万`。销售额超过 1000 万才开始盈利。

### 法务高频考点

| 法律 | 要点 |
| --- | --- |
| <span lang="ja" translate="no">著作権法</span> | 创作时自动产生，无需登记；程序受保护，但算法和编程语言本身不受保护 |
| <span lang="ja" translate="no">産業財産権</span> | 专利权（发明）、实用新型权（物品形状构造的小发明）、外观设计权、商标权，都需要申请登记 |
| <span lang="ja" translate="no">不正競争防止法</span> | 保护商业秘密（需满足秘密管理性、有用性、非公知性三个条件）、禁止盗用域名等 |
| <span lang="ja" translate="no">個人情報保護法</span> | 个人信息的取得、利用目的、第三方提供；“要配虑个人信息”需本人同意 |
| <span lang="ja" translate="no">サイバーセキュリティ基本法</span> | 规定国家和地方政府等在网络安全方面的责任和基本方针 |
| <span lang="ja" translate="no">不正アクセス禁止法</span> | 禁止冒用他人 ID 和密码、攻击安全漏洞、非法取得 ID 密码 |
| <span lang="ja" translate="no">労働者派遣法</span> | 派遣劳动者接受**派遣目的地**的指挥命令，但雇佣合同是和**派遣公司**签的 |
| <span lang="ja" translate="no">請負契約</span> | 承包：指挥命令权在**承包方**，委托方直接指挥承包方的员工就成了“伪装承包” |

**类题**：<span lang="ja" translate="no">A 社は B 社と請負契約を結び、B 社の社員が A 社内で作業している。適切なものはどれか。</span>

答案方向：A 社不能直接对 B 社的员工下达作业指示，指示应通过 B 社的负责人。这是承包与派遣最常考的区别。

### 经营战略与管理

战略框架（SWOT、PPM、安索夫、波特基本战略、BSC 等）在[经营战略笔记](/posts/business-strategy-frameworks/)里整理过。令和 6 年度出了 12 题，比往年多。

**类题**：<span lang="ja" translate="no">市場成長率が低く、市場占有率が高い事業は、PPM のどれに該当するか。</span>

答案：<span lang="ja" translate="no">金のなる木</span>（现金牛）。

| 新词 | 意思 |

## 二、管理系

### 开发技术

开发流程、测试方法、开发模型在[软件工程笔记](/posts/software-engineering-design-testing/)中有详细整理。高频概念：

| 用语 | 要点 |
| --- | --- |
| <span lang="ja" translate="no">ウォーターフォールモデル</span> | 按阶段顺序进行，原则上不回到前一阶段 |
| <span lang="ja" translate="no">アジャイル</span> | 短周期反复开发，重视变化；Scrum 中有 Sprint、产品负责人等 |
| <span lang="ja" translate="no">ブラックボックステスト</span> | 只看输入输出，不看内部结构（等价划分、边界值分析） |
| <span lang="ja" translate="no">ホワイトボックステスト</span> | 根据程序内部结构设计测试（命令覆盖、分支覆盖） |
| <span lang="ja" translate="no">回帰テスト（リグレッションテスト）</span> | 修改后确认其他部分没有受影响 |
| <span lang="ja" translate="no">DevOps</span> | 开发与运维协作，快速可靠地发布 |

### 项目管理

**关键路径（计算）**

**类题**：作业 A（3 天）→ B（4 天）→ D（2 天）；A 完成后也可以开始 C（6 天），C 完成后接 D。整个项目最短需要几天？

```text
路径 1：A → B → D = 3 + 4 + 2 = 9 天
路径 2：A → C → D = 3 + 6 + 2 = 11 天
最短工期 = 最长路径 = 11 天（关键路径 A→C→D）
```

关键路径上的作业延迟一天，整个项目就延迟一天；B 有 2 天的余裕。

令和 6 年度出现的“累加估算法”（<span lang="ja" translate="no">積み上げ法</span>）是一种成本估算方法：把 WBS 分解出来的每项作业的工时和成本逐一估算，再合计。与之相对的是类比估算法（参考过去类似项目）和功能点法（按功能的数量和复杂度估算）。

### 服务管理

| 用语 | 要点 |
| --- | --- |
| <span lang="ja" translate="no">SLA</span> | 服务提供方与用户之间关于服务水平的协议（可用率、响应时间等） |
| <span lang="ja" translate="no">インシデント管理</span> | 尽快恢复服务，优先恢复而不是找原因 |
| <span lang="ja" translate="no">問題管理</span> | 找出事件的根本原因，防止再发 |
| <span lang="ja" translate="no">変更管理・リリース管理</span> | 有计划地实施和发布变更 |
| <span lang="ja" translate="no">サービスデスク</span> | 用户的单一联络窗口（SPOC） |
| <span lang="ja" translate="no">システム監査</span> | 由独立于被审计对象的人员检查和评价 |

“事件管理”和“问题管理”的区别几乎每年都考：前者先恢复，后者找原因。

## 三、技术系

### 基础理论

进制转换、逻辑运算等内容可以看[数值表示笔记](/posts/number-representation-logic/)和[逻辑电路笔记](/posts/logic-operations-circuits/)。

**伪代码**是近年最难的题型，需要逐行追踪变量的值。IPA 公布了伪代码的书写规则，务必事先读一遍。

**类题**：下面的程序执行后，`total` 的值是多少？

```text
○整数型: i, total
total ← 0
for (i を 1 から 10 まで 1 ずつ増やす)
  if (i ÷ 3 の余りが 0)
    total ← total + i
  endif
endfor
```

```text
i = 3 → total = 3
i = 6 → total = 9
i = 9 → total = 18
结果：18
```

追踪时画一张表，列出每次循环的 i 和 total。题目常把程序挖掉一行，让你选填入的代码，这时先手算一个小例子，再逐个代入选项验证。

### 计算机系统

**可用率（计算）**

```text
可用率 = MTBF / (MTBF + MTTR)
串联：整体可用率 = A1 × A2         （都正常才能工作）
并联：整体可用率 = 1 − (1 − A1)(1 − A2)   （有一个正常即可）
```

**类题**：可用率 0.9 的两台装置并联，整体可用率是多少？

```text
1 − (1 − 0.9)(1 − 0.9) = 1 − 0.01 = 0.99
```

串联时是 `0.9 × 0.9 = 0.81`。并联提高可靠性，串联降低可靠性。

其他要点：RAID 0（条带化，无冗余）、RAID 1（镜像）、RAID 5（分布式奇偶校验）；虚拟化、云服务的 IaaS / PaaS / SaaS 区别。

### 技术要素：网络

网络部分在[OSI 与 TCP/IP 笔记](/posts/osi-tcp-ip-in-depth/)中有详细说明。令和 6 年度出现的新词：

| 用语 | 意思 |
| --- | --- |
| <span lang="ja" translate="no">準天頂衛星</span> | 日本的卫星定位系统“みちびき”，长时间停留在日本上空附近，提高定位精度 |
| <span lang="ja" translate="no">マルチホップ</span> | 数据经由多个终端接力传输的通信方式，用于传感器网络等 |
| <span lang="ja" translate="no">ESSID のステルス化</span> | 不在信标中发送无线网络名称，但不能代替加密 |

### 技术要素：安全（18 题，重点）

| 类别 | 用语 | 要点 |
| --- | --- | --- |
| 三要素 | 机密性、完整性、可用性 | C（Confidentiality）、I（Integrity）、A（Availability） |
| 威胁 | <span lang="ja" translate="no">ランサムウェア</span> | 加密数据并索要赎金；对策是离线备份 |
| | <span lang="ja" translate="no">DNS キャッシュポイズニング</span> | 向 DNS 缓存注入伪造信息，把用户引向假网站 |
| | <span lang="ja" translate="no">ダークウェブ</span> | 需要特殊软件访问的网络空间，常交易被盗信息 |
| | <span lang="ja" translate="no">ソーシャルエンジニアリング</span> | 利用人的心理弱点获取信息（冒充电话、偷看等） |
| 对策 | <span lang="ja" translate="no">WAF</span> | Web 应用防火墙，检查 HTTP 内容，防御 SQL 注入等 |
| | <span lang="ja" translate="no">バイオメトリクス認証</span> | 生物认证：指纹、静脉、人脸 |
| | <span lang="ja" translate="no">PIN</span> | 与特定设备绑定的短密码，配合设备使用 |
| | <span lang="ja" translate="no">Secure Erase</span> | 通过存储设备固件彻底消除 SSD 等的数据 |
| 风险 | <span lang="ja" translate="no">リスク回避・低減・移転（共有）・保有（受容）</span> | 买保险属于风险转移（共有） |
| 管理 | <span lang="ja" translate="no">情報セキュリティポリシー</span> | 基本方针 → 对策标准 → 实施程序三层结构 |
| 认证 | <span lang="ja" translate="no">ISMS クラウドセキュリティ認証</span> | 在 ISMS 认证基础上，对云服务追加的认证（基于 ISO/IEC 27017） |

**加密方式**是每年必考：

| | 共通键加密 | 公开键加密 |
| --- | --- | --- |
| 键 | 加密和解密用同一把键 | 公钥加密，私钥解密 |
| 速度 | 快 | 慢 |
| 键的管理 | 通信对象越多，键越多（n 人需 n(n−1)/2 把） | 每人一对 |
| 例 | AES | RSA |

**数字签名**用的方向相反：发送方用**自己的私钥**签名，接收方用**发送方的公钥**验证。它能证明“确实是本人发的”和“内容没有被篡改”，但不能保证机密性。

**类题**：<span lang="ja" translate="no">A さんが B さんに、内容を秘密にしてメールを送りたい。公開鍵暗号方式で暗号化するとき、使う鍵はどれか。</span>

答案：B さんの公開鍵。只有 B 的私钥能解密。容易错选成“A 的私钥”，那是数字签名的用法。

**类题**：10 人之间两两用共通键加密通信，需要多少把键？

```text
10 × 9 / 2 = 45 把
```

### 技术要素：数据库

每年约 3 题。要点：

- **主键**（<span lang="ja" translate="no">主キー</span>）：唯一确定一行，不能重复、不能为空。
- **外键**（<span lang="ja" translate="no">外部キー</span>）：引用另一张表的主键，保证参照完整性。
- **规范化**（<span lang="ja" translate="no">正規化</span>）：消除重复数据，避免更新异常。
- **SQL**：`SELECT 列 FROM 表 WHERE 条件`。
- **事务**：ACID（原子性、一致性、隔离性、持久性），通过提交、回滚、日志恢复保证。

**类题**：商品表中，满足“价格 1000 以上且分类为文具”的行，用哪一个 WHERE 条件？

```sql
WHERE 価格 >= 1000 AND 分類 = '文具'
```

题目里常把 AND 和 OR 互换来设陷阱。“且”用 AND，“或”用 OR。

## 复习建议

1. **先拿下安全和法务。** 这两部分题量大，而且以用语为主，投入产出比最高。
2. **计算题要动手。** 投资回收期、损益、关键路径、可用率每年都考，公式不难，但要亲手算过几遍才不会在考场出错。
3. **伪代码不要放弃。** 题数虽少，但难度高，平时练习逐行追踪变量的习惯。
4. **新词靠推测。** 每年都有大纲外的词，读题时从字面和上下文推测，不要慌。
5. **三个领域都要过 300 分。** 考前做一遍完整的公开问题，看每个领域的得分率。
