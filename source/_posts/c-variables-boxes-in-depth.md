[从零理解 C 语言中的变量](/posts/c-variables-from-zero/)讲了声明、初始化、赋值、输入输出和作用域。这一篇换一个角度，把变量想成一个贴了标签的盒子，继续追问几个初学时容易跳过的问题：盒子有多大，最多能装多大的数，装不下会怎样，字符为什么也能做加法，小数为什么会算不准，不同盒子之间倒来倒去会丢掉什么，以及盒子到底放在哪里。

每一节都按同一个顺序展开：先看一个基础例子，再改动一两个条件做变式，最后归纳出一条规律。目的不是背下每个例子的答案，而是学会一个例子之后，遇到同类问题能自己推出来。代码都可以放进 `main` 里运行，编译方式与上一篇相同：

```powershell
gcc -std=c17 -Wall -Wextra -Wpedantic boxes.c -o boxes.exe
.\boxes.exe
```

程序中的输出文字统一用英文，这样在 Windows 终端里不会因为编码设置出现乱码。

## 先用盒子模型记住变量的四个属性

看下面这一行：

```c
int age = 18;
```

可以把它读成：准备一个 `int` 规格的盒子，贴上标签 `age`，往里放进 18。

![int age = 18 的盒子模型：名字、类型、值和地址](/img/notes/c-variable-box-model.svg)

| 盒子模型 | C 语言中的说法 | 在 `int age = 18;` 中 |
| --- | --- | --- |
| 盒子上的标签 | 变量名 | `age` |
| 盒子的规格 | 类型 | `int`，决定能装多大的数、按什么规则计算 |
| 盒子里的东西 | 值 | 现在是 18 |
| 盒子所在位置的编号 | 地址 | 用 `&age` 取得，每次运行可能不同 |

从这个模型可以直接推出几条规则，后面的例子都会反复用到：

1. 一个盒子同一时间只装一个值。执行 `age = 19;`，18 就被替换掉，不会两个值同时存在。
2. 读取不会把东西拿走。`int copy = age;` 相当于把 `age` 里的值复印一份放进 `copy`，`age` 本身不变。
3. 两个盒子互不影响。复印之后再改 `age`，`copy` 不会跟着变。
4. 规格决定能装什么。把 3.9 放进 `int` 盒子，只会留下 3；把太大的数放进小盒子，会装不下。

盒子模型是为了帮助理解。实际运行时，编译器可能把变量放在寄存器里，甚至在优化后完全省掉某个变量，所以不必把每个变量都想成永远固定在某个格子里。不过在入门阶段，按盒子来推理不会得出错误结论。

先用前三条规则做一个小练习。预测最后 `x` 和 `y` 的值：

```c
int x = 5;
int y = x;
x = x * 2;
y = y + x;
```

答案是 `x` 为 10、`y` 为 15。第二行把 5 复印给 `y`；第三行只改 `x`，`x` 变成 10；第四行读取 `y` 当前的 5 和 `x` 当前的 10，相加后写回 `y`。

变式：把第三、第四行交换顺序。

```c
int x = 5;
int y = x;
y = y + x;
x = x * 2;
```

这次 `y` 先算，读取到的 `x` 还是 5，所以 `y` 为 10；之后 `x` 才变成 10。两段代码只差顺序，结果就不同。规律：每一条语句只读取变量“此刻”的值，程序从上往下一条一条执行。

## 用 sizeof 看看盒子有多大

`sizeof` 用来查询一个类型或一个变量占多少字节。字节（byte）是内存计量的基本单位，在几乎所有常见电脑上 1 字节等于 8 个二进制位（bit）。

```c
#include <stdio.h>

int main(void)
{
    printf("char:      %zu\n", sizeof(char));
    printf("short:     %zu\n", sizeof(short));
    printf("int:       %zu\n", sizeof(int));
    printf("long:      %zu\n", sizeof(long));
    printf("long long: %zu\n", sizeof(long long));
    printf("float:     %zu\n", sizeof(float));
    printf("double:    %zu\n", sizeof(double));

    return 0;
}
```

`sizeof` 的结果类型是 `size_t`，对应的格式说明是 `%zu`。如果使用很旧的 MinGW 发现 `%zu` 输出异常，可以临时改成 `printf("%d\n", (int)sizeof(int));`。

在常见的 64 位环境中，结果通常如下：

| 类型 | Windows 64 位 | Linux 和 macOS 64 位 | 标准保证的最低要求 |
| --- | --- | --- | --- |
| `char` | 1 | 1 | 恰好 1 字节 |
| `short` | 2 | 2 | 至少 16 位 |
| `int` | 4 | 4 | 至少 16 位 |
| `long` | 4 | 8 | 至少 32 位 |
| `long long` | 8 | 8 | 至少 64 位 |
| `float` | 4 | 4 | 由实现决定 |
| `double` | 8 | 8 | 由实现决定 |

注意 `long` 这一行：同样的代码，在 Windows 上是 4 字节，在 Linux 上是 8 字节。C 标准只规定了 `char` 是 1 字节，以及各整数类型的最低范围，其余大小由编译器和平台决定。所以不要把“`int` 是 4 字节”当成语言规定，需要确定大小时，用 `sizeof` 去查。

`sizeof` 也可以用在变量和表达式上：

```c
int n = 7;
double d = 2.5;

printf("%zu\n", sizeof n);        /* 与 sizeof(int) 相同 */
printf("%zu\n", sizeof d);        /* 与 sizeof(double) 相同 */
printf("%zu\n", sizeof(n + d));   /* int 与 double 相加，结果是 double */
```

第三行是一个变式：`n + d` 的结果类型是 `double`（原因见后面的类型转换一节），所以得到的是 `double` 的大小。再进一步，`sizeof(n + 1)` 得到的是 `int` 的大小，而 `sizeof(n + 1.0)` 得到的是 `double` 的大小，因为 `1.0` 本身就是 `double`。

规律：`sizeof` 看的是类型，不看具体的值。`int` 盒子里放 1 还是放一亿，盒子大小都一样。

## 从位数推出盒子能装多大的数

盒子能装多大的数，取决于它有多少个二进制位。每一位只有 0 和 1 两种状态，于是：

| 位数 | 所有组合 | 组合个数 |
| --- | --- | --- |
| 1 位 | 0、1 | 2 |
| 2 位 | 00、01、10、11 | 4 |
| 3 位 | 000 到 111 | 8 |
| n 位 | 每多一位，组合数翻倍 | 2ⁿ |

8 位就有 2⁸ = 256 种组合。怎么用这 256 种组合，有两种分法：

- 无符号（`unsigned`）：全部用来表示非负数，范围是 0 到 255。
- 有符号（`signed`，默认的 `int` 等都是有符号的）：一半给负数，一半给零和正数，范围是 −128 到 127。

为什么正数这边少一个？因为 0 占了非负数那一半中的一个位置：−128 到 −1 是 128 个，0 到 127 也是 128 个，合计 256。

把 8 换成任意的 n，就得到通用公式：

| 类型 | 最小值 | 最大值 |
| --- | --- | --- |
| n 位无符号 | 0 | 2ⁿ − 1 |
| n 位有符号 | −2ⁿ⁻¹ | 2ⁿ⁻¹ − 1 |

举一反三，套进不同的位数：

| 位数 | 无符号范围 | 有符号范围 |
| --- | --- | --- |
| 8 | 0 到 255 | −128 到 127 |
| 16 | 0 到 65535 | −32768 到 32767 |
| 32 | 0 到 4294967295 | −2147483648 到 2147483647 |

不需要背这些数字，`<limits.h>` 已经替我们准备好了：

```c
#include <stdio.h>
#include <limits.h>

int main(void)
{
    printf("CHAR_BIT  = %d\n", CHAR_BIT);
    printf("INT_MIN   = %d\n", INT_MIN);
    printf("INT_MAX   = %d\n", INT_MAX);
    printf("UINT_MAX  = %u\n", UINT_MAX);
    printf("LLONG_MAX = %lld\n", LLONG_MAX);

    return 0;
}
```

`CHAR_BIT` 是一个字节的位数，常见环境为 8。无符号的 `unsigned int` 用 `%u` 输出，`long long` 用 `%lld` 输出。

一个很实用的估算技巧：2¹⁰ = 1024，约等于一千。于是 2³¹ ≈ 2 × 10⁹，也就是说 32 位 `int` 大约能装到 21 亿。用这个估算来选类型：

| 要保存的数据 | 大约多大 | 32 位 `int` 够不够 |
| --- | --- | --- |
| 一个班的人数 | 几十 | 够 |
| 中国人口 | 约 14 亿 | 够，但离上限不远 |
| 世界人口 | 约 80 亿 | 不够，用 `long long` |
| 从 1970 年起算的毫秒数 | 约 1.7 × 10¹² | 不够，用 `long long` |

规律：先估算数据最大可能是多少，再选能装下它的盒子，并留出余量。

## 盒子装不下时就会溢出

无符号整数装不下时，会像汽车的里程表一样从头开始转。六位里程表走到 999999 再前进 1 公里，会显示 000000。

```c
unsigned char u = 255;
u = u + 1;
printf("%d\n", u);    /* 输出 0 */
```

过程是这样的：`u + 1` 先按 `int` 计算，得到 256；把 256 放回只能装 0 到 255 的 `unsigned char` 时，标准规定取除以 256 的余数，于是得到 0。

变式一：`u = 250; u = u + 10;`，260 除以 256 余 4，结果为 4。

变式二：无符号数减到负数以下，会从最大值那一头转回来。

```c
unsigned int count = 0;
count = count - 1;
printf("%u\n", count);    /* 在 32 位 unsigned int 上输出 4294967295 */
```

这在实际程序中很危险：比如用无符号变量记录剩余次数，减过头之后不会变成 −1，而是变成一个巨大的数。

有符号整数溢出则完全不同。

```c
int big = INT_MAX;
big = big + 1;    /* 未定义行为 */
```

`INT_MAX + 1` 超出了 `int` 的范围，这在 C 语言中属于未定义行为。很多人测试时看到它变成了 `INT_MIN`，但这不是标准保证的结果，开启优化后编译器可能做出完全意想不到的处理。正确做法是在计算之前先检查：

```c
int a = 2000000000;
int b = 500000000;

if (b > 0 && a > INT_MAX - b) {
    printf("overflow\n");
} else {
    printf("%d\n", a + b);
}
```

`a + b > INT_MAX` 这种写法本身就要先算 `a + b`，所以没有用；改写成 `a > INT_MAX - b`，就只在安全范围内做减法。

下面是初学者最常踩的一个溢出陷阱：

```c
int seconds_per_day = 24 * 60 * 60;                     /* 86400 */
long long ms_per_year = seconds_per_day * 1000 * 365;   /* 错误 */
```

左边虽然是 `long long`，但右边三个操作数都是 `int`，乘法会先按 `int` 完成：86400 × 1000 = 86400000 还在范围内，再乘 365 得到 31536000000，已经超过约 21 亿的上限，在存进 `long long` 之前就溢出了。改法是让乘法一开始就按 `long long` 进行：

```c
long long ms_per_year = (long long)seconds_per_day * 1000 * 365;
```

或者把某个常量写成 `1000LL`，`LL` 后缀表示这是一个 `long long` 常量。

这和上一篇中 `double average = 5 / 2;` 得到 2.0 是同一条规律：右边先按自己的类型算完，再把结果放进左边的盒子。左边的盒子再大，也救不回右边已经算错的结果。

## char 盒子里装的其实是小整数

```c
char letter = 'A';
printf("%c %d\n", letter, letter);    /* A 65 */
printf("%c\n", letter + 1);           /* B */
```

`char` 盒子里存的并不是图形“A”，而是它的编码。常见环境使用 ASCII 兼容编码，`'A'` 的编码是 65。用 `%c` 输出，`printf` 按编码画出对应字符；用 `%d` 输出，就直接看到这个数。`letter + 1` 得到 66，用 `%c` 输出就是 `B`。

几个需要分清的写法：

| 写法 | 是什么 | 数值 |
| --- | --- | --- |
| `0` | 整数零 | 0 |
| `'0'` | 字符零 | 48 |
| `"0"` | 字符串，包含字符 `'0'` 和结尾的空字符 | 不是单个数 |
| `'\0'` | 空字符 | 0 |

既然字符就是数，就可以用减法算出它们之间的距离，这个思路能推出一整组用法。

字符数字转成数值：

```c
char digit = '7';
int value = digit - '0';    /* 55 - 48 = 7 */
```

C 标准保证 `'0'` 到 `'9'` 的编码是连续的，所以任何数字字符减去 `'0'`，都能得到它代表的数。反过来，`3 + '0'` 得到字符 `'3'`。

小写字母转大写：

```c
char lower = 'c';
char upper = lower - 'a' + 'A';    /* 'C' */
```

`lower - 'a'` 先算出它是第几个字母（从 0 开始，`'c'` 是 2），再加上 `'A'`，就落到大写字母的同一位置。依此类推：

- 大写转小写：`upper - 'A' + 'a'`。
- 字母在字母表中的序号（从 1 开始）：`ch - 'a' + 1`，`'e'` 得到 5。
- 字母后移三位：`'a' + 3` 是 `'d'`，这就是凯撒密码的起点。

字母连续排列是 ASCII 的性质，标准本身只对数字作了这样的保证；在常见的电脑环境中都可以这样使用。另外，一个汉字在 UTF-8 中通常占 3 个字节，放不进一个 `char`，处理中文需要字符串，这部分以后再学。

规律：字符可以参与整数运算，“减去起点字符”得到偏移量，“偏移量加上起点字符”回到字符。

## 小数盒子保存的是近似值

```c
#include <stdio.h>

int main(void)
{
    double a = 0.1;
    double b = 0.2;

    printf("%.2f\n", a + b);         /* 0.30 */
    printf("%.17f\n", a + b);        /* 0.30000000000000004 */
    printf("%d\n", a + b == 0.3);    /* 0 */

    return 0;
}
```

保留两位小数时看起来一切正常，显示 17 位就露出了误差，用 `==` 比较的结果是 0，也就是“不相等”。

原因和十进制写不尽 1/3 一样。1/3 在十进制下是 0.333…，永远写不完；0.1 在二进制下也是无限循环小数，`double` 只能保存一个最接近的近似值。0.1 和 0.2 的近似值相加，和 0.3 的近似值并不完全相同。数值在计算机中的表示方式，可以参考[数值表示笔记](/posts/number-representation-logic/)。

判断两个小数“是否相等”，应当判断它们的差是否足够小：

```c
#include <math.h>

if (fabs((a + b) - 0.3) < 1e-9) {
    printf("equal enough\n");
}
```

`fabs` 求绝对值，`1e-9` 表示 10⁻⁹。在 Linux 上使用 `<math.h>` 的函数时，编译命令末尾可能需要加 `-lm`。

`float` 的盒子比 `double` 小，近似得更粗。`float` 大约有 6 到 7 位有效数字，`double` 大约有 15 到 16 位。

```c
float f = 16777217;
printf("%.1f\n", f);    /* 16777216.0 */
```

16777217 是 2²⁴ + 1，超出了 `float` 能精确表示的整数范围，存进去就变成了 16777216。整数放进 `float` 也可能丢失精度。

由此可以推出几条习惯：

- 写小数时默认用 `double`。`3.14` 本身就是 `double`，写成 `3.14f` 才是 `float`。
- 不要用 `==` 直接比较两个计算出来的小数。
- 金额这类要求分毫不差的数据，用整数记录最小单位，例如用“分”而不是“元”，上一篇的找零程序就是这样做的。

## 不同盒子之间倒值时会发生转换

把值从一种类型的盒子倒进另一种类型的盒子，或者让两种类型一起运算，都会发生类型转换。规则可以归纳成四条。

第一条，小盒倒进大盒，值不变：

```c
int i = 42;
double d = i;         /* 42.0 */
long long big = i;    /* 42 */
```

第二条，小数倒进整数盒子，直接丢掉小数部分，向零截断，而不是四舍五入：

| 表达式 | 结果 |
| --- | --- |
| `(int)3.9` | 3 |
| `(int)3.1` | 3 |
| `(int)-3.9` | −3 |

对非负数，想要四舍五入，可以先加 0.5 再截断：`(int)(3.6 + 0.5)` 得到 4，`(int)(3.4 + 0.5)` 得到 3。负数这样做会出错，那时可以使用 `<math.h>` 中的 `lround`。

第三条，整数和小数一起运算，整数先被转换成小数：

| 表达式 | 结果 | 原因 |
| --- | --- | --- |
| `5 / 2` | 2 | 两边都是 `int`，做整数除法 |
| `5 / 2.0` | 2.5 | `5` 先转成 `double` |
| `5.0 / 2` | 2.5 | `2` 先转成 `double` |
| `(double)5 / 2` | 2.5 | 先把 5 转换，再做除法 |
| `(double)(5 / 2)` | 2.0 | 括号里已经按整数算完 |

第四条，有符号和无符号一起运算时，有符号的一方可能被转成无符号，这一条最反直觉：

```c
int a = -1;
unsigned int b = 1;

if (a < b) {
    printf("a < b\n");
} else {
    printf("a >= b\n");    /* 实际输出这一行 */
}
```

比较之前，`a` 的 −1 被转换成 `unsigned int`，按前面里程表的规则变成了 4294967295，于是它比 1 大。使用 `-Wall -Wextra` 编译时，GCC 会对这种比较给出警告，看到 `comparison of integer expressions of different signedness` 时就要小心。`sizeof` 的结果也是无符号的，所以 `-1 < sizeof(int)` 同样为假。最简单的避免方法是：不需要无符号时，就不要用无符号类型。

整数除法和取余在遇到负数时也有固定规则。C99 起规定整数除法向零截断，并且总满足：

```text
a == (a / b) * b + a % b
```

| 表达式 | 结果 | 用上式检验 |
| --- | --- | --- |
| `7 / 2`、`7 % 2` | 3、1 | 3 × 2 + 1 = 7 |
| `-7 / 2`、`-7 % 2` | −3、−1 | −3 × 2 + (−1) = −7 |
| `7 / -2`、`7 % -2` | −3、1 | −3 × (−2) + 1 = 7 |
| `-7 / -2`、`-7 % -2` | 3、−1 | 3 × (−2) + (−1) = −7 |

可以看出，余数的符号总是和被除数 `a` 相同。由此推出一个常见错误：用 `n % 2 == 1` 判断奇数，对 −3 会得到 `-3 % 2` 为 −1，判断失败。正确写法是 `n % 2 != 0`。

## 复合赋值和自增自减是更新变量的简写

| 简写 | 等价写法 |
| --- | --- |
| `x += 3;` | `x = x + 3;` |
| `x -= 3;` | `x = x - 3;` |
| `x *= 3;` | `x = x * 3;` |
| `x /= 3;` | `x = x / 3;` |
| `x %= 3;` | `x = x % 3;` |
| `x++;` 或 `++x;` | `x = x + 1;` |
| `x--;` 或 `--x;` | `x = x - 1;` |

复合赋值的右边是一个整体。

```c
int x = 4;
x *= 2 + 3;    /* x = x * (2 + 3)，结果是 20，不是 11 */
```

`x++` 和 `++x` 单独成为一条语句时效果完全相同。只有放进更大的表达式里，它们才有区别：

```c
int a = 5;
int b = a++;    /* 先把 5 交给 b，再让 a 变成 6 */
int c = ++a;    /* 先让 a 变成 7，再把 7 交给 c */
```

执行后 `a` 为 7、`b` 为 5、`c` 为 7。记法：`++` 写在后面，就是“先用后加”；写在前面，就是“先加后用”。

不要在同一个表达式里多次修改同一个变量，例如 `i = i++;` 或 `a++ + a++`。这些写法在 C 语言中属于未定义行为，不同编译器可能给出不同结果，考试题里出现也只说明这是错误写法。最稳妥的习惯是把自增单独写成一行。

练习：逐行跟踪 `n` 的值。

```c
int n = 10;
n += 5;
n /= 4;
n %= 2;
n *= 3 + 1;
n--;
```

答案依次是 15、3（整数除法）、1、4、3，最终 `n` 为 3。

## 每个盒子都有自己的位置编号

```c
#include <stdio.h>

int main(void)
{
    int a = 10;
    int b = 10;

    printf("a = %d, address = %p\n", a, (void *)&a);
    printf("b = %d, address = %p\n", b, (void *)&b);

    return 0;
}
```

某次运行的输出可能是：

```text
a = 10, address = 000000000061FE1C
b = 10, address = 000000000061FE18
```

`&` 是取地址运算符，`&a` 得到盒子 `a` 所在的位置编号，用 `%p` 输出，并按要求转换成 `void *`。具体数字每台电脑、每次运行都可能不同，重要的是两点：两个变量即使值相同，地址也不同，说明它们是两个独立的盒子；同一个变量在一次运行中的地址不会变，变的只是盒子里的值。

这就解释了为什么 `printf` 只要 `age`，而 `scanf` 要 `&age`：

```c
int age = 0;
scanf("%d", &age);
printf("%d\n", age);
```

`printf` 只需要知道盒子里现在装着什么，所以给它值的副本就够了。`scanf` 要把读到的数放进盒子，必须知道盒子在哪里，所以要给它地址。好比请人往你家送东西，需要给门牌号，而不是给一张房子的照片。

专门用来保存地址的变量叫指针，例如 `int *p = &a;`。指针是后面单独学习的内容，这里先记住“地址就是盒子的位置编号”就够了。

## 用除法和取余拆出每一位数字

这一节把前面的整数除法、取余和变量更新结合起来。给定一个三位数，分别求出百位、十位和个位：

```c
#include <stdio.h>

int main(void)
{
    int n = 365;

    int hundreds = n / 100;
    int tens = n / 10 % 10;
    int ones = n % 10;

    printf("hundreds = %d, tens = %d, ones = %d\n", hundreds, tens, ones);
    printf("sum = %d\n", hundreds + tens + ones);
    printf("reversed = %d\n", ones * 100 + tens * 10 + hundreds);

    return 0;
}
```

输出为：

```text
hundreds = 3, tens = 6, ones = 5
sum = 14
reversed = 563
```

逐个理解：

- `n / 100`：365 里有 3 个完整的 100，所以百位是 3。
- `n / 10 % 10`：`/` 和 `%` 优先级相同，从左往右算。先 `365 / 10` 得到 36，去掉了个位；再 `36 % 10` 得到 6，取出新的最后一位。
- `n % 10`：365 除以 10 的余数是 5，就是个位。

归纳成一条规律：从个位数起，第 k 位（个位 k = 0）等于 `n / 10ᵏ % 10`。“除以 10ᵏ”把右边不要的位去掉，“对 10 取余”只留下最后一位。

有了这条规律，可以推出一系列变式。

变式一，四位数 2026：千位 `n / 1000` 为 2，百位 `n / 100 % 10` 为 0，十位 `n / 10 % 10` 为 2，个位 `n % 10` 为 6。

变式二，判断三位数是否为回文数，例如 121：只需要比较 `ones == hundreds`，相等时结果为 1。

变式三，把 10 换成 2，就能拆出二进制位。以 13 为例，从低位起依次是 `13 % 2` 为 1、`13 / 2 % 2` 为 0、`13 / 4 % 2` 为 1、`13 / 8 % 2` 为 1，从高位往低位读就是 1101。

变式四，把 10 换成 60，就是上一篇里把秒数换算成时、分、秒的方法：秒是 `t % 60`，分是 `t / 60 % 60`，时是 `t / 3600`。

还要注意两个边界。把 120 反转，得到 `0 * 100 + 2 * 10 + 1` 即 21，开头的 0 不会显示出来；如果输入的是 1234，`n / 100` 会得到 12，不再是一位数，说明程序只对三位数成立，需要先检查输入范围。

## 用常见错误反查漏掉的规则

| 现象或写法 | 问题所在 | 改法 |
| --- | --- | --- |
| `printf("%d", sizeof(int));` | `sizeof` 结果是 `size_t` | 使用 `%zu` |
| 以为 `long` 一定是 8 字节 | 大小由平台决定 | 用 `sizeof` 确认，或使用 `long long` |
| `int` 乘法结果很大，存进 `long long` 仍然错误 | 右边先按 `int` 计算并溢出 | 先转换一个操作数，或使用 `LL` 后缀 |
| `unsigned` 计数减到 0 以下变成巨大的数 | 无符号数从最大值转回 | 减之前检查，或改用有符号类型 |
| `char c = '5'; int d = c;` 得到 53 | 保存的是字符编码 | 写成 `c - '0'` |
| `if (a + b == 0.3)` 永远不成立 | 小数是近似值 | 比较差的绝对值是否足够小 |
| `(int)2.7` 得到 2 | 转换是截断，不是四舍五入 | 非负数用 `(int)(x + 0.5)` |
| `n % 2 == 1` 判断不出负奇数 | 余数符号与被除数相同 | 写成 `n % 2 != 0` |
| `-1 < 1u` 为假 | −1 被转换成无符号的最大值 | 避免混用有符号和无符号 |
| `x *= 2 + 3` 结果比预期大 | 右边整体先求值 | 记住等价于 `x = x * (2 + 3)` |
| `i = i++;` 在不同编译器结果不同 | 同一表达式多次修改同一变量 | 把自增单独写成一行 |

## 先预测结果再做分层练习

### 第一层检查盒子装不下时的结果

先预测，再运行验证：

```c
unsigned char u = 200;
u = u + 100;

char ch = 'a' + 2;
int k = ch - 'a';
```

答案：`u` 为 44，因为 300 除以 256 余 44；`ch` 为 `'c'`；`k` 为 2。

变式：把第一行改成 `unsigned char u = 0;`，第二行改成 `u = u - 1;`，结果是 255。

### 第二层检查负数的除法和取余

```c
int a = 17;
int b = -5;
```

求 `a / b`、`a % b`、`-a / b`、`-a % b`。

答案依次为 −3、2、3、−2。可以用 `(a / b) * b + a % b == a` 逐个检验，例如 (−3) × (−5) + 2 = 17。

### 第三层把字符规律迁移到新问题

已知两个字符变量 `char c1 = '7';` 和 `char c2 = '8';`，写出一个表达式，得到整数 78。

答案是 `(c1 - '0') * 10 + (c2 - '0')`。变式：三个字符 `'2'`、`'0'`、`'5'` 组成 205，写成 `(c1 - '0') * 100 + (c2 - '0') * 10 + (c3 - '0')`。这正好是上一节拆位的反向操作。

### 第四层独立选择合适的类型

编写程序，分别计算并输出一天和一年（按 365 天）有多少毫秒。要求先估算结果大小，再为每个变量选择类型。

一天是 86400000 毫秒，`int` 可以装下；一年是 31536000000 毫秒，超过约 21 亿，需要 `long long`，输出时使用 `%lld`，并且乘法要从一开始就按 `long long` 计算。完成后，可以故意把类型改回 `int`，打开 `-Wall -Wextra` 重新编译，观察编译器是否给出溢出警告，以及运行结果变成了什么。

## 一条规律对应一组题目

| 规律 | 本文中的例子 | 还能迁移到 |
| --- | --- | --- |
| 语句按顺序执行，只读取变量此刻的值 | 交换两行语句后结果不同 | 循环中的计数器、累加器 |
| 右边先按自己的类型算完，再放进左边 | `int` 乘法溢出后存入 `long long` | `5 / 2` 存入 `double`，任何混合类型赋值 |
| n 位能表示 2ⁿ 种值 | `char`、`int` 的取值范围 | 任意位数的类型，IP 地址、颜色值 |
| 无符号数按里程表方式回绕 | `255 + 1` 得到 0 | 计数器减过头，有符号与无符号比较 |
| 字符就是编码，可以相减得偏移 | `'7' - '0'`，大小写转换 | 字母序号，凯撒密码 |
| 除以基数去掉低位，对基数取余留下最后一位 | 拆出百位十位个位 | 二进制位，时分秒换算 |
| 小数是近似值 | `0.1 + 0.2 != 0.3` | 金额用整数分记录 |

学习新内容时，可以照着这个表的方式问自己：这个例子背后的规律是什么，把哪个条件换掉，就能得到一道新的题目。
